# Manufacturing Yield & SPC Dashboard

A command-line Python tool that turns raw production-line data into the
numbers a process technician actually watches day to day: first-pass yield,
rolled throughput yield, a defect Pareto, X-bar and R control charts, and
process capability (Cp / Cpk) for a critical dimension — plus a Markdown
summary report with root-cause prompts.

Author: **Sri Charan Kotha**

> **About the data:** the bundled `data/sample_production.csv` is
> **synthetic data generated by `scripts/generate_sample_data.py`**
> (fixed seed, ~5,000 units across 2 lines x 4 weeks). It is not real
> production data and is not from any employer. The tool itself works on
> any CSV with the same columns.

## Why this project exists

It maps directly to the day-to-day work of a manufacturing process
technician — the kind of role described in the Tesla NCM Process
Technician posting (Buffalo, NY, Req 259251):

| Job duty (from the posting) | What this tool does |
|---|---|
| Day-to-day coverage of the production line | One command summarises a whole day/week of line output |
| Rapid response on out-of-control processes | X-bar / R charts flag subgroups outside the control limits in red, and the report counts them |
| Root-cause analysis and countermeasures | The report lists the out-of-control subgroups and the Pareto head, with prompts for 5 Whys / fishbone follow-up |
| Summarise and analyse yield and process data | FPY, RTY, weekly yield trend chart, defect Pareto |
| Support Lean / continuous improvement / 5S | Re-run after every countermeasure to confirm the process is back in control — the improvement loop |
| Use tools to manage and interpret data (Tableau, SQL) | Same analytical outputs (yield, Pareto, SPC) produced here in Python/pandas; the CSV is SQL-friendly and the report is Markdown |

No Tesla experience is claimed anywhere in this project — the job posting
is used only as the requirements source for what to build.

## What it computes

- **First-pass yield (FPY)** — good units / total units, overall and per line.
- **Rolled throughput yield (RTY)** — product of the three process-step
  first-pass yields. Steps: Forming (crack, dimension defects), Coating
  (scratch, contamination), Final check (other). Standard textbook form,
  documented in `spc_dashboard.py`.
- **Defect Pareto** — counts by category with cumulative %, as a chart
  and a table.
- **X-bar and R control charts** — rational subgroups of 5 consecutive
  measurements per line, standard constants (A2 = 0.577, D3 = 0,
  D4 = 2.114). Out-of-control points are highlighted.
- **Process capability Cp / Cpk** — for the critical dimension against
  the spec limits (default LSL 9.90 mm, USL 10.10 mm, nominal 10.00 mm).

## Quick start

```bash
pip install -r requirements.txt

# Regenerate the synthetic sample data (optional — a copy is bundled)
python scripts/generate_sample_data.py

# Run the dashboard on the sample data
python spc_dashboard.py

# Or point it at your own CSV with the same columns
python spc_dashboard.py --input path/to/production.csv --output my_report
python spc_dashboard.py --lsl 9.90 --usl 10.10 --subgroup-size 5
```

## Input format

One row per unit produced:

| Column | Meaning |
|---|---|
| `date` | Production date (YYYY-MM-DD) |
| `line` | Production line, e.g. `Line A` |
| `shift` | `Day`, `Swing`, or `Night` |
| `unit_id` | Unique unit identifier |
| `defect_category` | `none` for a good unit, else `scratch`, `contamination`, `crack`, `dimension`, or `other` |
| `dimension_mm` | Critical-dimension measurement (mm) |

Lines starting with `#` are ignored, so the synthetic-data banner in the
sample file does not affect parsing.

## Sample output (on the bundled synthetic data)

```
Units: 5,083  Defects: 150  FPY: 97.05%  RTY: 97.07%
  Line A: FPY 97.70%  RTY 97.72%
  Line B: FPY 96.40%  RTY 96.44%
  Line A: Cp 1.68  Cpk 1.68  (mean 9.9998 mm, sigma 0.0198 mm)
  Line B: Cp 1.16  Cpk 1.06  (mean 10.0084 mm, sigma 0.0288 mm)
  Overall: Cp 1.33  Cpk 1.27  (mean 10.0041 mm, sigma 0.0251 mm)
  Line A: 2 out-of-control X-bar subgroups, 4 out-of-control R subgroups
  Line B: 80 out-of-control X-bar subgroups, 5 out-of-control R subgroups
```

The sample data deliberately contains an out-of-control period — Line B,
week 3 (2026-10-19 to 2026-10-22), where the process mean shifts
+0.06 mm and the defect rate jumps to 9% — so the X-bar chart shows a
run of points beyond the upper control limit and Line B's Cpk drops to
1.06 (marginal — below the 1.33 "capable" threshold). That is the signal
a process technician is paid to catch.

Outputs (in `output/` by default):

- `report.md` — Markdown summary: yield tables, Pareto table, Cp/Cpk
  table with verdicts, out-of-control findings, and next-step prompts.
- `xbar_chart.png`, `r_chart.png` — control charts, one panel per line.
- `pareto_chart.png` — defect Pareto with cumulative-% line.
- `yield_trend.png` — weekly first-pass yield by line.
